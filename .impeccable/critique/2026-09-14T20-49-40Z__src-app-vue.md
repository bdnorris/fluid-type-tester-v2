## Overall Impression

The sitting that matters — drag min / fluid / max on Alice, then take clamp CSS — is real. Getting into that sitting is not. Controls start hidden then collapsed, fonts load as empty selects, and resizing the window (the job for fluid type) wrecks a three-column layout instead of isolating a preview width. The single biggest opportunity: make the preview a resizable stage and put the three clamp sliders on screen from the first second.

## What's Working

1. **Real prose at a real measure.** Alice (and the other `texts.json` titles) at 69ch is how type should be judged — not pangrams in a card.
2. **Clamp CSS is the actual takeaway when you get there.** The overlay emits real `clamp(min, calc(1rem + N vw), max)` that matches the sliders, including ratio-derived heading levels.
3. **Notes match the brand.** First-person, credits neighbors, no fake category positioning. Header Ratio only after Add Another Heading Level is the right kind of progressive disclosure.

## Priority Issues

### [P0] Preview has no isolated viewport
- **What:** The job is watch type respond as the viewport changes. The UI is a page-level `1fr 3fr 1fr` grid. At ~375px with Controls open, the preview is a ~175px rag; headings shatter; the sample title clips. No width ruler, no resizable frame, no 320/768/1440 presets.
- **Why it matters:** Fluid type is the product. Resizing the browser currently tests the chrome, not the type.
- **Fix:** One persistent preview stage with a width readout (and optional drag). Keep Controls from stealing the sample column.
- **Suggested command:** /impeccable adapt

### [P0] Primary controls start hidden, then collapsed
- **What:** Controls + is a 90°-rotated edge tab (`controlsVisible = false`). Header Text and Body Text default collapsed. First sitting: find tab → open drawer → expand Header → then sliders. No visible product name or “start here.”
- **Why it matters:** A no-account sitting will bounce before touching min / fluid / max.
- **Fix:** Dock Header + Body sliders on desktop. Keep Ratio, extra heading levels, and CSS as secondary. Title the page Fluid Type Tester with a one-line prompt.
- **Suggested command:** /impeccable layout

### [P1] Font pairing is a blank control
- **What:** Header Font and Body Font are empty comboboxes when `VITE_GF_API_KEY` is missing. No selected Roboto, no catalog-failed copy. Custom font is the only working path; Show CSS still omits `font-family`.
- **Why it matters:** The sitting is pair fonts and clamp. A blank select reads as broken.
- **Fix:** Curated fallback list without an API key; show current family; include `font-family` in CSS; empty/error copy when the catalog fails.
- **Suggested command:** /impeccable harden

### [P1] CSS takeaway isn’t copyable or complete
- **What:** SHOW CSS opens a scaled overlay with Headline / Paragraphs `<pre>` blocks. No Copy. No fonts. Escape does nothing. Focus jumps to the SHOW CSS trigger (`id="close-popup"`). Not a dialog.
- **Why it matters:** Frontend success is paste-into-a-PR. Hunt-and-select plus incomplete rules wastes the sitting.
- **Fix:** Primary Copy CSS; include families; Esc + focus trap + labelled dialog.
- **Suggested command:** /impeccable distill

### [P2] Sample and scale fight each other
- **What:** Extra heading levels inject Lorem into Alice. Sample picker `#articles` has no label. Header Ratio has no visible number. Body slider rows don’t match Header. Edit Content has no in/out chrome.
- **Why it matters:** Undermines “preview on real prose.”
- **Fix:** Pull extra headings from the selected text; label the picker; show Ratio as a number; unify slider rows.
- **Suggested command:** /impeccable clarify

## Questions to Consider

- If the product is clamp-on-prose, why isn’t the preview a resizable stage with a width readout, instead of “resize the whole app”?
- Why are min / fluid / max — the only durable controls — behind a drawer that starts closed and sections that start collapsed?
- If the sitting ends with CSS, why isn’t Copy the one obvious button, with fonts included?
- What would a confident lab look like with Controls always visible and Notes/CSS as drawers — not the reverse?
- Should “Fluid” be visible in the chrome (ruler, current px) so a first-timer doesn’t have to already know to squeeze the window?
